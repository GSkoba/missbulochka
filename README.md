# 🐾 Pet Clinic

## 🎯 Цель

Разработать **production-подобный прототип** ветеринарной клиники (Pet Clinic),
демонстрирующий инженерную зрелость и владение современным Go-стеком.

### Ключевые цели

* Проектировать и реализовать систему с **чистой архитектурой (hexagonal)**
* Показать умение работать с:

  * транзакциями, валидацией, обработкой ошибок
  * миграциями и типобезопасным доступом к БД
  * логированием, метриками и контейнеризацией
* Написать тесты (юнит и интеграционные), настроить CI
* Принять и зафиксировать архитектурные решения (**ADR**)

## 🧱 Архитектура

**Тип:** Port-Adapter (Hexagonal / Clean Architecture)

```
cmd/petclinic/        # Точка входа
internal/app/         # Инициализация, DI, wire-up
internal/domain/      # Доменные сущности и правила
internal/usecase/     # Бизнес-сценарии (интерфейсы портов)
internal/adapter/http # Handlers, DTO, middleware, validation
internal/adapter/repo # Работа с БД (Postgres, Redis)
pkg/                  # Общие утилиты (логгер, метрики, ошибки)
```

**Принципы**

* DTO ≠ Domain
* Глобальный middleware ошибок → JSON-ответ `{code, message, details}`
* Все операции через `context.Context`, таймауты на I/O
* **Graceful shutdown** (обработка сигналов)
* Транзакции через `pgx.Tx` / `sqlc`
* **Idempotency-Key** для создания визитов (через Redis)
* **Optimistic Locking** по `version` или `updated_at`

## 📦 Домен и функциональные требования

### Основные сущности

* **Owner** — владелец питомца
* **Pet** — питомец
* **Vet** — ветеринар
* **Visit** — визит питомца к врачу
* **Specialty** — справочник специализаций врачей

### Функции

* CRUD для Owner, Pet, Vet
* Расписание визитов:

  * создать визит
  * перенести визит
  * отменить визит (с указанием причины)
  * завершить визит
* Поиск:

  * Owners → по фамилии / телефону / email (с пагинацией и сортировкой)
  * Pets → по типу / владельцу
  * Visits → по дате / врачу / статусу / диапазону дат


## ⚖️ Бизнес-правила

* Нельзя записать визит в прошлое
* В один и тот же тайм-слот у одного Vet не может быть двух визитов
* При отмене визита фиксируется причина
* **Optimistic Locking** на Visit и Vet (`version` или `updated_at`)
* **Уникальный индекс** `vet_id + start_time` предотвращает коллизии
* **Seed-данные** (через миграции): 3–5 записей на каждую сущность

## 📚 Подсказки

* **Идемпотентность:**
  `SET key value NX PX <ttl>` → при повторе возвращать сохранённый результат
* **Коллизии визитов:**
  Уникальный индекс `(vet_id, start_time)` + `unique_violation` → HTTP 409
* **Ошибки:**
  Sentinel errors + `errors.Is/As`, маппинг доменных в HTTP-коды
* **Транзакции:**
  Usecase открывает `Tx`, передаёт `dbtx` в репозитории
* **Профилирование:**
  `/debug/pprof` endpoint (*stretch*)
